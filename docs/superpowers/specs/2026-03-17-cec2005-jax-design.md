# CEC 2005 JAX Implementation Design

**Date:** 2026-03-17
**Status:** Approved

## Overview

Implement all 25 CEC 2005 benchmark functions in JAX, integrated into `bbob-jax` alongside the existing BBOB suite. Functions must be JIT-compilable, automatically differentiable via `jax.grad`, and vectorizable via `jax.vmap`. The public API mirrors the existing BBOB registry pattern exactly.

## Important Deviation from Official CEC 2005

This implementation replicates the CEC 2005 function **formulas only**. Parameters (shift vectors, rotation matrices, auxiliary matrices) are generated from seeds rather than loaded from the official CEC 2005 data files. Results will **not** match published CEC 2005 benchmarking results. This deviation is documented at the top of `cec2005.py` and in each affected function's docstring.

## Function Signatures

### Simple functions (F1–F14)

Internal signature matches BBOB exactly:

```python
def fn(x, x_opt, f_opt, R, Q) -> jax.Array
# x:     (..., ndim)
# x_opt: (ndim,)
# f_opt: scalar
# R, Q:  (ndim, ndim)  — functions that don't use Q receive identity
```

### Hybrid composition functions (F15–F25)

Same signature, batched parameter shapes:

```python
def fn(x, x_opt, f_opt, R, Q) -> jax.Array
# x:     (..., ndim)
# x_opt: (num_components, ndim)     — one optimum per component
# f_opt: scalar                     — global offset
# R, Q:  (num_components, ndim, ndim) — one rotation matrix per component
```

All functions are exposed as `fn(x)` after partial application via `jax.tree_util.Partial` — the shape difference is invisible to the user.

### Composition function structural constants

All structural parameters of the composition functions that are **not** randomizable — `sigma` (basin widths), `lambda_` (scaling factors), `bias` (per-component offsets), component function list, and any special conditioning — are **hardcoded constants** inside each function's implementation in `cec2005.py`. They are taken from the CEC 2005 technical report (Suganthan et al., 2005) and are never passed through the registry factory.

This means the factory only generates: `x_opt`, `f_opt`, `R`, `Q`. The special structural differences between F15–F25 variants (e.g. narrow basin in F19, boundary-clamped optimum in F20, ill-conditioned matrix in F22) are embedded directly in each function's implementation — they are not controlled by registry parameters.

The `bias` vector for all composition functions is `[0, 100, 200, 300, 400, 500, 600, 700, 800, 900]` (10 components). The first component always has `bias[0] = 0`.

**JAX JIT note:** The component function list (`fns`) passed to `hybrid_composition` is always bound at construction time as a Python-level constant — it is never a JAX-traced argument. `hybrid_composition` is an internal utility that is never directly JIT-compiled with `fns` as a dynamic input; JIT compilation always happens after `fns` is fixed via the function closure.

## Registry Design

Two new factory functions added to `registry.py`:

### `make_randomized_cec2005(fn, ndim, key, num_components=1)`

- `num_components=1`: generates scalar shapes (same as BBOB)
- `num_components>1`: generates batched shapes; `x_opt: (num_components, ndim)`, `R/Q: (num_components, ndim, ndim)` via stacked calls to `rotation_matrix`
- `x_opt`: sampled uniformly from `[-100, 100]^ndim` (CEC 2005 domain, vs BBOB's `[-4, 4]`)
- `f_opt`: Cauchy-sampled, clipped to `[-1000, 1000]` (same as BBOB)
- `R`, `Q`: via existing `rotation_matrix` utility, stacked for composition functions
- **Key splitting:** Keys are always derived as `keys = jr.split(key, 2 * num_components + 2)`, giving independent subkeys for each of the `num_components` R matrices, `num_components` Q matrices, one key for `x_opt` (further split per row via `jr.split(keys[-2], num_components)`), and one key for `f_opt`. This applies for **all** values of `num_components`, including `num_components=1` — the existing BBOB `make_randomized` pattern of reusing `key1` for both `x_opt` and `R` is intentionally not replicated here.

### `make_deterministic_cec2005(fn, ndim, key=None, num_components=1)`

- Zero `x_opt`, zero `f_opt`, identity `R`/`Q`
- When `num_components > 1`: `x_opt` is `jnp.zeros((num_components, ndim))`, `R`/`Q` are `jnp.stack([jnp.eye(ndim)] * num_components)`
- `key=None` parameter accepted and ignored, keeping call convention identical to `make_randomized_cec2005` so both registries are drop-in interchangeable in tests

### Registry dicts

```python
cec2005_registry          # name → Partial(make_randomized_cec2005, fn=..., num_components=...)
cec2005_registry_original # name → Partial(make_deterministic_cec2005, fn=..., num_components=...)
```

These are distinct from the existing BBOB `registry` and `registry_original` — they coexist in `registry.py` as separate dicts and are exported under their own names. The `cec2005_` prefix makes the separation explicit.

Call convention identical to BBOB:
```python
fn, f_opt = cec2005_registry["f1"](ndim=10, key=k)
value = fn(x)  # shape: ()
```

`num_components` per function is hardcoded in the registry entry via `Partial`. All composition functions (F15–F25) use `num_components=10`.

**Note on existing typo:** The existing BBOB factory is named `make_determinstic` (missing `i`) — this typo is intentionally left unchanged to avoid breaking existing call sites. The new CEC 2005 factory uses the correct spelling `make_deterministic_cec2005`.

## Tags / Metadata

`cec2005_tags.py` exports `cec2005_function_characteristics`, a `defaultdict` with one entry per function.

**Schema keys:** `unimodal`, `multimodal`, `composition`, `rotated`, `noise_omitted`, `structure_modified`

**Invariants:**
- `unimodal` and `multimodal` are mutually exclusive
- `composition=True` always implies `multimodal=True`
- `noise_omitted=True` means the function is noisy per the CEC 2005 spec but noise is absent in this implementation for JAX grad compatibility
- `structure_modified=True` means the function's mathematical structure has been altered (beyond parameter generation) for JAX compatibility — currently only F23, where the non-continuous rounding step is omitted entirely

## Special Cases

| Function | Issue | Resolution |
|----------|-------|------------|
| F4 | Gaussian noise in fitness breaks `jax.grad` | Noise omitted; documented in docstring and `noise_omitted` tag |
| F5 | Requires fixed auxiliary matrix A | A generated deterministically from seed |
| F12 | Requires fixed auxiliary matrices A, B | A, B generated deterministically from seed |
| F17 | Gaussian noise in fitness | Noise omitted; documented in docstring and `noise_omitted` tag |
| F23 | Non-continuous rounding operation | Rounding step omitted entirely — F23 is implemented as a continuous version of F22; flagged via `structure_modified=True` tag and documented in docstring |

## New Utilities in `utils.py`

Base component functions needed by CEC 2005 (not present in current `utils.py`):
- `ackley(x)` — Ackley base function
- `griewank(x)` — Griewank base function
- `scaffer_f6(x, y)` — Scaffer's F6 2D kernel
- `cec2005_weierstrass(x)` — Weierstrass kernel with CEC 2005 parameters (`a=0.5`, `b=3.0`); uses 21 terms: `k = 0, 1, ..., 20` (i.e. `jnp.arange(0, 21)`). Named distinctly from the existing BBOB `weierstrass` utility, which uses 12 terms (`jnp.arange(0, 12)`) — no refactor of the existing function needed.
- `hybrid_composition(x, fns, sigma, lambda_, bias, x_opt, R, Q)` — composition kernel used by F15–F25; applies `R` and `Q` per-component (some variants use both rotations per the CEC 2005 paper); `fns` is a Python list of callables bound at construction time and never a JAX-traced argument

## Testing

Parametrized over all 25 functions × `[2, 3, 5, 10, 20]` dimensions × both registries. Each test validates:

1. Correct scalar output shape
2. JIT compilation (`jax.jit`)
3. Vectorization (`jax.vmap`)
4. Gradient computation (`jax.grad`)

**Composition function sanity check (F15–F25):** With `cec2005_registry_original` (deterministic, `f_opt=0`), the test constructs the evaluation point as `x_test = jnp.zeros(ndim)` — which equals `x_opt[0]` under the deterministic factory (all component optima are zero). The test verifies: (a) `fn(x_test)` returns a finite scalar, and (b) the gradient magnitude `jnp.linalg.norm(jax.grad(fn)(x_test))` is small (below a loose tolerance, e.g. `ndim * 10.0`). The test does not access `x_opt` directly from the returned `(fn, f_opt)` tuple — the zero construction is valid because the deterministic factory guarantees `x_opt = jnp.zeros(...)`. A global equality assertion (`fn(x_test) == bias[0]`) is not used because nonzero weights from the other 9 components prevent exact equality at finite distances.

The noise-free deviation for F4/F17 and the seed-generated parameter deviation for F5/F12 are documented in a module-level docstring at the top of `cec2005.py` and in each affected function's docstring.
