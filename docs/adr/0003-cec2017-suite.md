# ADR 0003: CEC 2017 suite — code-wins ground truth, seed-generated instances, `min_ndim`

- Status: accepted
- Date: 2026-07-10

## Context

The CEC 2017 bound-constrained suite (Awad et al., 2016) was added as the
third benchmark family. Its technical report and its official reference
code (`cec17_test_func.c`) disagree in several load-bearing places, the
official instances live in data files defined only for D ∈ {10, 20, 30,
50, 100}, F2 was withdrawn from the competition after publication, and the
hybrid functions introduce structural constraints (one dimension per
subcomponent kernel) that no earlier suite had. The repo's existing
conventions — seed-generated instances with a `deterministic=True` variant,
`fn(x_opt) == f_opt` as a tested invariant, NaN-in → NaN-out (BBOB), and
softjax only where JAX's gradient is degenerate — all had to be reconciled
with the official semantics.

## Decision

1. **Code wins.** The implementation follows the official reference code
   wherever it disagrees with the report, because the code is what every
   published result ran; each divergence is documented in the function
   docstring. Consequences faithfully replicated: F6's rotation is dead
   code (the kernel reads the pre-rotation shift buffer; shift-only,
   `rotated=False`), F8's non-continuity transform never executes (it is
   plain shifted-rotated Rastrigin), F9 applies no shrink and its true
   minimizer is `x_opt + R.T @ ones` (handled by an `x_opt_from`
   resolver), the hybrid Schaffer F7 sub-kernel (F14, F20) reads the
   leading shuffled coordinates instead of its own chunk, and F13's
   Lunacek sign flip reads the leading unshuffled shift entries.
2. **F2 is excluded** and the numbering keeps the hole
   (`cec2017_f1`, `cec2017_f3` … `cec2017_f30`), matching the reference
   code and data files; the "final version updated" report's 1–29
   renumbering is not followed.
3. **Instances are seed-generated** (shift in [-80, 80]^D, random
   rotations, random hybrid shuffle permutations, sampled `f_opt`),
   consistent with the other suites; the official data files are not
   shipped. Correctness is instead established by
   `scripts/crosscheck_cec2017.py`, which injects the official data files
   into the bbob-jax definitions and compares point-for-point against the
   *compiled* official code — all 29 functions match at D ∈ {10, 30}
   to within the documented epsilon guards (relative error ≤ ~1e-9,
   machine epsilon for most functions).
4. **`min_ndim` is a first-class field** on `FunctionSpec` and `Problem`;
   makers raise `ValueError` below it. Hybrid chunk sizes come from
   `cec2017_hybrid_partition`: the reference `ceil` split (bit-identical
   double math) wherever it is well-defined, and a largest-remainder
   split with per-kernel minimum sizes at the dimensions where `ceil`
   breaks (e.g. F20 at D=11 has a negative last chunk in the reference —
   out-of-bounds UB). Both coincide with the exact proportional split at
   every officially supported dimension.
5. **No softjax; epsilon-guarded `jnp.sqrt` instead.** `sj.sqrt` maps NaN
   to 0 and would break the suite's NaN-in → NaN-out guarantee (tested,
   like BBOB's). Nothing in the suite has a degenerate gradient that
   epsilon guards cannot handle: F8's rounding is dead code, F7/F13's
   sign flips are static per instance, and the quarter/half-power kernels
   (HappyCat, HGBat) use `(|v| + eps)^p - eps^p` so the optimum value
   stays exact and the gradient finite. Hybrids carry an exact-zero
   `0.0 * sum(y)` term so NaN propagates through coordinates the
   reference ignores.

## Consequences

- Published CEC 2017 tables are not reproducible from the registries
  (sampled instances), but the function *definitions* are validated
  against the true reference, and anyone can re-run the cross-check.
- Downstream dimension sweeps must respect `Problem.min_ndim` (up to 7
  for F20; compositions F29/F30 need 5). The landscape gallery renders
  such functions as documented 2D slices through the optimum plane.
- Deterministic composition instances (F21–F30) are degenerate exactly
  like the deterministic CEC 2005 compositions (all component shifts
  coincide), documented on `Problem.x_opt`.
